## Timebox (by deployment mode)

The "2–3 days" RAD promise is a floor, not a wish. Tech Lead fills this table during `/setup` based on northstar §7c (Deployment Mode) and §12 (Feature Grouping).

### Mode: `pwa` (2-day target)

| Day | Morning | Afternoon | Gate |
|---|---|---|---|
| Day 1 | `/phase1` → `/phase2` → human runs Claude Design → `/design verify` | `/phase4` → `/setup` → Foundation (backend + frontend + landing + auth) | Foundation green at EOD |
| Day 2 | Wave 1 features (`/feature` per feature) | Wave 2 features + `/dogfood` + `/pre-handoff` | Deploy to production (`/deploy`) |

### Mode: `native` (3-day target)

| Day | Morning | Afternoon | Gate |
|---|---|---|---|
| Day 1 | `/phase1` → `/phase2` → human runs Claude Design → `/design verify` | `/phase4` → `/setup` → Backend + Web Frontend Foundation | Web landing deployed |
| Day 2 | `/native-init` + Mobile Foundation | Wave 1 features (web + mobile) | Mobile dev build on simulator green |
| Day 3 | Wave 2 features | `/dogfood` → `/pre-handoff` → `/deploy` → `/store-submit` | App submitted to TestFlight / Play internal |

### Mode: `pwa-then-native` (2 days PWA + 2 days native later)

Day 1–2 matches `pwa` mode. Native follows in a separate sprint:

| Native day | Morning | Afternoon | Gate |
|---|---|---|---|
| Native Day 1 | `/native-init` + Mobile Foundation | Wave 1 screens (translated from web handoff) | Dev build green |
| Native Day 2 | Remaining screens + push setup | `/dogfood` → `/store-submit` | Submitted |

If a feature looks like it'll spill past its day, the Tech Lead cuts scope rather than extending. Scope cuts go into northstar §8 (Not Building) with a one-line reason.
